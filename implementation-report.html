五、偏离规范的两处（需你裁定）

① subagent propose 的处置功能缺口
规范
§2.4 / §5.1 / §7 三处均写：P1 起 subagent propose ⇒ candidate（走 reconcile 裁决）
实现
一律拒绝并返回明确文案；candidate 只由 extract 产生
影响
subagent 无法贡献记忆。安全侧更严（不弱化任何边界），但少了一条规范承诺的输入通道
建议
P1 实测后再定：若 subagent 贡献确有价值则补 8 行；否则把规范收敛到「拒绝」
② global 库 guard 只做了一半按阶段合理
规范
§2.2「库级双向 guard」：global 拒非 private，repo 拒 private
实现
只建 repo 侧两个 trigger；global 侧注释说明随 P2 迁移引入
影响
无。§2.5 明确 P0/P1 不启用 global 库——为不存在的库建 guard 正是规范自己拒绝的「预刻」
建议
维持；启用 global 库的迁移必须同时建该 trigger（已写在代码注释）

六、阶段完成度

P0 ✓ 完成Store + 原子迁移 + 三工具 + 同步 propose→active + forget + 来源抑制
