# 0005 · 召回未命中率只做筛查信号，不作为引入 embedding 的判据

- 日期：2026-08-23
- 状态：已采纳
- 相关：阶段 4、`src/metrics.ts`、[`0002`](0002-l2-l3-need-defined-boundaries.md)、[`0004`](0004-l3-rebuild-trigger.md)

## 背景

设计文档把「向量检索 + RRF」从**永久拒绝**改为**阶段 4 待验证项**，前置条件是
「先用 §9 metrics 采集召回未命中率，有数据再做」。

动手前先问了一个问题：**这个数真能回答那个决定吗？** 实测后答案是**不能**。

## 关键发现

一次「零命中」在数据上**无法区分**三种截然不同的情况：

| 类别 | 含义 | 向量检索能否解决 |
|---|---|---|
| **A** | 库里确实没有这条知识 | ❌ 无中生有 |
| **B** | 库里有，但**措辞/词形没对上** | ✅ **正是它能救的** |
| **C** | 模型随口一探，本就不期待命中 | — 无需解决 |

**只有 B 支持引入 embedding 依赖**，而任何计数器都分不开这三类——区分它们需要
知道「本该命中什么」，那是**标注数据，不是算术**。

若把 A+B+C 混成一个「未命中率 40%」，再拿它去论证「该上向量检索了」，就是
本项目两次否决过的同一错误（连续 trust 公式、L2/L3 语义未定）：**一个带着
无人能论证之阈值的数字**。

## 决定

**采集它，但明确定性为「筛查信号」而非「判据」**，并把这个限制写在产出它的
代码注释里，而不是只写在文档里。

- 高未命中率的正确解读是「**去读转写**」，不是「加向量」；
- 判定 B 类的真正证据在 **L0**：*未命中 → 模型改写查询 → 命中同一条*
  ——同一意图换个词就找到了，这才是「FTS 词形不够」的铁证；
- 因此**不新建计数器**：`recall` 工具的输出本就被 L0 记录，未命中率是
  **一条 SQL**，且 L0 同时保留了未命中前后的上下文——正是区分三类所需的材料。

## 实现

```
recallCalls     = count(conversations where label='tool:memory_recall')
recallMissRate  = 其中以 RECALL_NO_MATCH 开头的比例
```

零新增列、零计数器，符合 §9「全部由 SQL 快照算出，绝不在内存累积」。

**一处耦合已显式化**：指标依赖工具渲染的那句 `No stored memories matched.`。
它已提为共享常量 `RECALL_NO_MATCH`，并有回归测试——**改了措辞而忘了指标，
会导致此后永远统计到 0 次未命中，决定就建立在一个悄悄失效的数字上**。
（实测：把该字符串改掉，测试立即失败。）

## 2026-08-28 校准：B 类里先分出「分词损耗」

实测：B 类（有但措辞没对上）在中文里**多数不是语义问题，而是分词问题**。默认
分词器对标点之间的 CJK 只产出一个 token，故查询须等于整段才命中——真实记忆上
`分词器`/`工程取舍`/`真相源`/`记忆库`/`连续词组` 全部 0 命中。

这不推翻本 ADR，而是**收紧其用法**：遇到 B 类先问「换个分词方案还落空吗」，
再问「是否需要 embedding」。前者一次索引重建即可，后者要引入模型依赖。顺序
颠倒，就是用昂贵机制去补一个便宜缺陷。

**方案选择过程（记录否决项，因为它不显然）**：`trigram` 能修中文，但实测会让
`CI`/`Go`/`L3`/`v9` 这类 <3 字符标识符**从能搜变成搜不到**（本语料 163 个），
并引入跨词边界误命中（`cat` 命中 `concatenate`）——**用一个回归换一个修复，
不可接受**。自定义 tokenizer 需编译 C 扩展，违反零依赖约束。最终采用
**CJK bigram 索引**（schema v9）：保留 `unicode61` 使英文与既有语义原样不动，
另把 CJK 重叠二元组索引到 `cjk` 列，读侧按同一规则展开查询。它严格优于
trigram——连 `取舍` 这样的二字词也能命中——且仍是一条 FTS 查询、一个 `rank`，
未新增与 `memory_recall` 竞争的第二条检索规则。

**推论**：v9 之前采集的未命中率**不能**直接用于 embedding 判断——它把分词损耗
混了进来。重估前需用现在的索引重新采集。

## 代价（如实记录）

- 该指标**不能单独支撑**「引入 embedding」的决定，永远需要人读转写来确认 B 类。
  这是如实承认，不是缺陷——假装一个数字能决定它才是缺陷。
- ~~L0 有 90 天保留期，故该比率是**近 90 天窗口**，非全历史。对趋势判断足够。~~
  **⛔ 这句话是错的（2026-09-01 更正）。该比率是全历史，且会单调稀释。**

  两个前提各自不成立：① `metrics.ts:77-86` 的两条 SQL **没有任何时间谓词**，
  它 count 的是 `conversations` 里**全部** `label='tool:memory_recall'` 行；
  ② 即便有，`pruneConversations` 也**从不删除任何行**——豁免子句使保护集恒等于
  全集（实测 2026-09-01：9 库 6813/6813 行、311/311 条 recall 行全部被钉住；
  把窗口强行开到 `now+1d` 仍删 0 行）。**没有任何机制会让一条 recall 行老化出去。**

  **后果比措辞失真严重**：本 ADR 把该比率定为「阶段 4（引入 embedding）」的
  前置采集信号，而一个全历史比率会**随时间单调稀释**——早期未命中永久留在分母，
  数字越来越好看，却不反映**现在**的检索质量。按滚动窗口读它，会在
  「最近很糟」时看到「总体尚可」。

  > **今天两者数值恰好相同，所以这个错误在数据上不可见**：语料跨度仅 8.0 天
  > （2026-08-24…09-01）＜ 90 天，滚动窗口与全历史返回同一批行。
  > **它只能从代码看出来，看不出来的错误正是最该写下来的那种。**
  > 详见 [`docs/audit-2026-09-01-l0-retention.md`](../audit-2026-09-01-l0-retention.md)。

  **重估 embedding 前必须先解决口径**：或给 metrics 加时间窗，或明确接受
  全历史口径并在解读时扣除。**本轮只登记，不改 `metrics.ts`**——改动它会移动
  本 ADR 赖以决策的那个数字，属独立评估。

## 替代方案

- *记录每条未命中的查询串*：需新表或新列，且**仍分不开 A/B/C**——多花机制，
  不多回答问题。
- *直接上向量检索*：正是「无数据支撑」所要避免的。
- *什么都不采集*：那 §12 的前置条件永远无法满足，阶段 4 会被无限期悬置。

## 口径补记（2026-08-31）：这个分母至今没有量对过东西

一次为推进阶段 4 而做的审计，查到的结果是**该指标从未采集到一个可用样本**。
记在这里，是因为下一个人几乎一定会重新看到那个数字并试图据以决策。

全部 7 个 repo 库，`label='tool:memory_recall'` 共 **306** 行，分解如下：

```
306 = 118 (Error 行) + 81 (空库上的必然未命中) + 42 (非空库未命中) + 65 (命中)
```

**三层污染，每一层都让分子分母量的不是同一件事：**

1. **118 条 `Error:` 行**（占 38.6%）是 `sourceOf` 空串 bug 的产物，
   最近一条 2026-08-24，该 bug 由 `059e0ce` 修复，之后为 0。它们是错误，
   不是未命中，却坐在分母里。
2. **306 次调用中 294 次（96.1%）来自三次批量导入会话**——「让另一个 AI 把
   历史决策导入记忆库」的作业，用户指令明写「按连续中文短语查重…导入后再次
   核验」。这是**查重探针**，按本文的分类整类是 **C（随口一探，本就不期待
   命中）**，且是被指令强制发起的 C。真实的组织性使用只有 **12 次**。
3. **123 次未命中里有 81 次（65.9%）发生在该库还一条记忆都没有的时候**
   ——那是 A 类，而且是逻辑上必然的 A 类，不需要任何判断。

**结论：剔掉 Error 行得到的 65.4%，与原来的 40.2% 一样不是「组织性使用的
召回未命中率」。** 它是「批量查重作业的探针未命中率」。两个数都干净，
两个数都量错了东西。

**故本文的门禁不设阈值，也不该设。** 「有效样本达到 N 次」是一个无人能论证
的数字，用它当门禁，就是把本文自己否决过的「无数据支撑的阈值」换个位置再犯
一次。判据仍然只有一条，且是定性的：**比率显著，且抽读 L0 确认存在
「未命中 → 改写查询 → 命中同一条」的实例**——而这要求分母里首先得有
组织性使用。

**一个方法论教训**（本项目第四次同型）：识别出「分母里有不该在的东西」之后，
必须继续问「**剩下的分母量的是同一件事吗**」。剔除污染只是第一步；
`ADR 0008` 记的「分子分母必须量同一件东西」在这里是第二层——
**口径干净 ≠ 分母量对了东西。**
