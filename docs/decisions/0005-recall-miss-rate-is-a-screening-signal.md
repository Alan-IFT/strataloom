# 0005 · 召回未命中率只做筛查信号，不作为引入 embedding 的判据

- 日期：2026-08-23
- 状态：已采纳
- 相关：阶段 4、`src/metrics.ts`、[`0002`](0002-l2-l3-need-defined-boundaries.md)、[`0004`](0004-l3-rebuild-trigger.md)

## 背景

设计文档把「向量检索 + RRF」从**永久拒绝**改为**阶段 4 待验证项**，前置条件是
「先用 §9 metrics 采集召回未命中率，有数据再做」。

动手前先问了一个问题：**这个数真能回答那个决定吗？** 实测后答案是**不能**。

## 关键发现

一次「零命中」在数据上**无法区分**三种截然不同的情况：

| 类别 | 含义 | 向量检索能否解决 |
|---|---|---|
| **A** | 库里确实没有这条知识 | ❌ 无中生有 |
| **B** | 库里有，但**措辞/词形没对上** | ✅ **正是它能救的** |
| **C** | 模型随口一探，本就不期待命中 | — 无需解决 |

**只有 B 支持引入 embedding 依赖**，而任何计数器都分不开这三类——区分它们需要
知道「本该命中什么」，那是**标注数据，不是算术**。

若把 A+B+C 混成一个「未命中率 40%」，再拿它去论证「该上向量检索了」，就是
本项目两次否决过的同一错误（连续 trust 公式、L2/L3 语义未定）：**一个带着
无人能论证之阈值的数字**。

## 决定

**采集它，但明确定性为「筛查信号」而非「判据」**，并把这个限制写在产出它的
代码注释里，而不是只写在文档里。

- 高未命中率的正确解读是「**去读转写**」，不是「加向量」；
- 判定 B 类的真正证据在 **L0**：*未命中 → 模型改写查询 → 命中同一条*
  ——同一意图换个词就找到了，这才是「FTS 词形不够」的铁证；
- 因此**不新建计数器**：`recall` 工具的输出本就被 L0 记录，未命中率是
  **一条 SQL**，且 L0 同时保留了未命中前后的上下文——正是区分三类所需的材料。

## 实现

```
recallCalls     = count(conversations where label='tool:memory_recall')
recallMissRate  = 其中以 RECALL_NO_MATCH 开头的比例
```

零新增列、零计数器，符合 §9「全部由 SQL 快照算出，绝不在内存累积」。

**一处耦合已显式化**：指标依赖工具渲染的那句 `No stored memories matched.`。
它已提为共享常量 `RECALL_NO_MATCH`，并有回归测试——**改了措辞而忘了指标，
会导致此后永远统计到 0 次未命中，决定就建立在一个悄悄失效的数字上**。
（实测：把该字符串改掉，测试立即失败。）

## 2026-08-28 校准：B 类里先分出「分词损耗」

实测：B 类（有但措辞没对上）在中文里**多数不是语义问题，而是分词问题**。默认
分词器对标点之间的 CJK 只产出一个 token，故查询须等于整段才命中——真实记忆上
`分词器`/`工程取舍`/`真相源`/`记忆库`/`连续词组` 全部 0 命中。

这不推翻本 ADR，而是**收紧其用法**：遇到 B 类先问「换个分词方案还落空吗」，
再问「是否需要 embedding」。前者一次索引重建即可，后者要引入模型依赖。顺序
颠倒，就是用昂贵机制去补一个便宜缺陷。

**方案选择过程（记录否决项，因为它不显然）**：`trigram` 能修中文，但实测会让
`CI`/`Go`/`L3`/`v9` 这类 <3 字符标识符**从能搜变成搜不到**（本语料 163 个），
并引入跨词边界误命中（`cat` 命中 `concatenate`）——**用一个回归换一个修复，
不可接受**。自定义 tokenizer 需编译 C 扩展，违反零依赖约束。最终采用
**CJK bigram 索引**（schema v9）：保留 `unicode61` 使英文与既有语义原样不动，
另把 CJK 重叠二元组索引到 `cjk` 列，读侧按同一规则展开查询。它严格优于
trigram——连 `取舍` 这样的二字词也能命中——且仍是一条 FTS 查询、一个 `rank`，
未新增与 `memory_recall` 竞争的第二条检索规则。

**推论**：v9 之前采集的未命中率**不能**直接用于 embedding 判断——它把分词损耗
混了进来。重估前需用现在的索引重新采集。

## 代价（如实记录）

- 该指标**不能单独支撑**「引入 embedding」的决定，永远需要人读转写来确认 B 类。
  这是如实承认，不是缺陷——假装一个数字能决定它才是缺陷。
- L0 有 90 天保留期，故该比率是**近 90 天窗口**，非全历史。对趋势判断足够。

## 替代方案

- *记录每条未命中的查询串*：需新表或新列，且**仍分不开 A/B/C**——多花机制，
  不多回答问题。
- *直接上向量检索*：正是「无数据支撑」所要避免的。
- *什么都不采集*：那 §12 的前置条件永远无法满足，阶段 4 会被无限期悬置。
