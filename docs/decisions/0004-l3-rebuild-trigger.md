# 0004 · L3 画像的重建触发：由模型判断，不设阈值

- 日期：2026-08-23
- 状态：已采纳（阶段 3 据此实施）
- 相关：D9、D10、[`0002`](0002-l2-l3-need-defined-boundaries.md)、`docs/design/4x4-memory.md` §1

## 背景

设计写明 L3「仅在长期趋势变化时重建（低频）」。这句话读起来像需要一个
**度量**，而度量意味着**阈值**——正是本项目已否决过一次的东西（连续 trust
公式，理由：阈值没有数据支撑）。

动手前实测了三条事实，它们改变了问题的形状：

1. **D9 会删掉画像**。任何一条 personal 记忆写入都触发失效，与「不随单条
   偏好抖动」直接冲突。
2. **个人偏好永远不会溢出预算**。20 条约 440 tok，预算 1300。L2 的触发器
   （`packetOverflows`）对 L3 **根本不适用**。
3. **L3 的价值不在压缩**。原子偏好 39 tok vs 画像 15 tok，差别微不足道；
   真正的差别是 L1 是**规则清单**、L3 是**一致的人格判断**——后者能外推到
   没写过的情形。

## 决定

**触发条件 = 画像缺失，或模型判定它已过时。**

在既有的维护轮（`maintain`，每 6 小时一次，已在跑）里对全局库执行：

- 画像不存在 ⇒ 入队重建；
- 画像存在 ⇒ 把「现有画像 + 当前 personal 记忆」交给模型，只问一个问题：
  *这份画像是否仍准确描述此人？* 回答"是"就保留，"否"则重写。

**不新增**：阈值、计数器、时间窗、`last_rebuilt_at` 列、新的 job kind
（复用 `rebuild`，按 store kind 分派）。

**D9 保持不变**（第二项决定）。画像被删后由下一次维护轮重建；模型若判定
内容未变，写回的就是同一份，对模型而言无感。缺失窗口内注入退化为原子
偏好——仍然可用，只是少了外推能力。

**判定频率由 snapshot 决定，不由维护周期决定**（2026-08-28 按实测校准）：
job 的幂等键含 `store_revision`，故**每个 snapshot 至多判定一次**——store 未变
时后续维护轮折叠到已执行的那次，不重复发问。这是有意的：输入没变还重问，
只是烧 token。因此本文原先「下一轮会再问一次」应读作**画像缺失或 snapshot
变化时才再问**；照实修正，避免 revision 与维护周期同时充当真相源。

## 理由

1. **代码算不出「这个人变了」**。它是语义判断。任何计数式代理指标（改了
   N 次、过了 N 天）与「人格是否变化」都没有必然关系：一天内修五个错字
   不代表人变了，半年后一句「以后都用英文」却代表变了。既然判断只能由
   模型做，就直接问它，而不是先用代码猜一个近似、再让模型收拾。
2. **符合既有原则**：「模型智能优先于代码，代码掌握权限/事务/安全边界」。
   重建时机是产品判断，不属于后者。
3. **不动 D9 就不必为它开例外**。为画像豁免 D9，意味着在 SQL 触发器里引入
   「按 kind 区分」的分支，使 D9 从一条规则变成带例外的规则——本项目刚用
   两轮代价消除这类复杂度（D7–D9）。用「删了就重建」把问题消解掉更便宜。
4. **成本已被现有机制约束**：维护轮 6 小时一次，判断走 leased job，继承
   fencing 与忙碌 agent 让路，无需新的并发故事。

## 代价（如实记录）

- 每个判断花一次 LLM 调用（低频；无 `llm` 服务时不入队，画像缺失，注入
  退化为原子偏好——与今天行为一致）。
- 模型可能判断失误：该重建时说"仍准确"。后果是画像陈旧，非数据损坏；下次
  重问发生在 personal 记忆再次写入（snapshot 前进）之时，而非固定周期。
- 判定**失败**时，dead-letter 曾把「下次再说」变成「永不再说」：同 id 的重新
  入队被 `ON CONFLICT DO NOTHING` 吸收。实测——global 库画像 job 在 revision 3
  死信后，跨五天维护轮均未重建。修法不在 L3 特判，而在唯一入队点：**failed
  行遇新触发即复活**（pending/running/done 照旧吸收），并把失败原因记在
  `jobs.last_error`（schema v8），因为日志会轮转而结论需要证据。
- 画像在两次维护轮之间可能短暂缺失。可接受：注入退化而非失效。

## 替代方案

- *计数阈值（变动 N 次后重建）*：零 LLM 成本，但 N 无数据支撑，且与"人变了"
  无因果关系。与被否决的 trust 公式同形。
- *定时重建（每 N 天）*：最简单，但无变化时白烧 token，有剧变时又要等周期；
  N 同样是拍脑袋。
- *为画像豁免 D9*：见理由 3。
