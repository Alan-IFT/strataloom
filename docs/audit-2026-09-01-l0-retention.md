## 一、结论

`pruneConversations`（`src/store/conversations.ts:97`）**当前删除量恒为 0**，
且不是「还没到期」，而是**豁免子句使保护集恒等于全集**。L0 因此**无上界增长**。

### ⛔ 范围更正：不是「三处失真」，是**五处**

初稿把失真点定为三处（`constants.ts`、规范 931、`conversations.ts` 注释）。
QA 普查 `grep -rn "90 天\|90 days\|L0_RETENTION"` 后查出**漏了两处**，
其中一处比原三处都严重：

| # | 位置 | 性质 | 处置 |
|---|---|---|---|
| 4 | **`docs/decisions/0005:82`** | **一个活的决策指标口径失真**：称 `recallMissRate` 是「近 90 天窗口」，实为**全历史且单调稀释**——`metrics.ts:77-86` 无时间谓词，且 prune 从不删行 | **已更正并登记** |
| 5 | `packages/memory/README.md:63` | 用户可见文档称 "pruned after 90 days" | 已改写 |
| — | `docs/decisions/0010:214` | 「`conversations`（90 天）」 | 已加更正注 |

> **第 4 处是本轮最有价值的发现，而它差点被漏掉**：ADR 0005 用该比率
> 决定「要不要上 embedding」。全历史比率会让早期未命中永久留在分母，
> **数字随时间单调变好看**，按滚动窗口读它会在「最近很糟」时看到「总体尚可」。
> 今天语料跨度 8.0 天 < 90 天，**两种口径返回同一批行，故该错误在数据上完全不可见**
> ——只能从代码看出来。**看不出来的错误正是最该写下来的那种。**
>
> **教训**：定义「有几处失真」时，凭阅读印象列举必然漏。**普查要用 grep，
> 且分母是全仓而不是记得的那几个文件。**

## 二、反事实实测（决定性）

把保留窗口**强行开到最大**（cutoff = `now + 1 天`，即一切行都「过期」），
用**逐字节照抄的生产谓词**执行：

```
cutoff = now+1d，9 库全部：
  rows deleted 0 / 6813 = 0.0%
  bytes freed  0 / 4,964,787 = 0.0%
```

再**单独**只留引用豁免子句、去掉时间条件：

```
citation predicate ALONE (no time bound): 0 / 6813
```

**两个对照合起来定性**：时间条件贡献 0 次删除，**决定一切的是引用豁免**。
所以「等到 2026-11-21 就会开始删」是错的——届时删除量仍是 0。

逐库豁免率（分母＝该库全部 L0 行）：

```
18 / 18 会话被钉住 = 100%      6813 / 6813 行 = 100%      4,964,787 / 4,964,787 字符 = 100%
```

> **单位**：全文凡由 SQLite `length(text)` 得出的量都是**字符**（码点），
> 不是字节；本机 L0 语料实测 UTF-8 膨胀 **1.32×**。比率不受影响
> （分子分母同单位），**绝对量与跨系统对照必须换算**——§五就是在这里栽过。

## 三、根因：两把尺子量的不是同一个容器

| 位置 | 粒度 |
|---|---|
| 写侧 `extract.ts:316` `sessionRef = payload.sessionId` | 证据 `ref` 记的是**整个会话** |
| 写侧 `extract.ts:390` `candidate.sourceSeqs` | 记忆真正引用的是**若干 seq 行** |
| 删侧 `conversations.ts:103` `session_id NOT IN (...)` | 豁免按**整个会话**生效 |

一条记忆只引用几行，却**永久钉住它所在的整个会话**。放大倍数实测：

```
豁免钉住的 L0            : 4,964,787 字符
回退路径最多可能返回的量 :   457,986 字符（每会话 SOURCE_TURN_LIMIT=34 行尾巴）
放大                     : 10.8×      死重 90.8%
```

**一条记忆钉住多少字节**（口径必须写明，否则同一问题有两个答案）：

| 口径 | n | p50 | max |
|---|---|---|---|
| **B：每条引用记忆钉住的整会话字节**（「一条记忆钉住多少」的诚实答案） | 410 | **274,228** | **966,733** |
| A：会话字节 ÷ 该会话引用数，再按**会话**取分位 | 18 | 10,313 | 71,937 |

> **⛔ 初稿只印了 A，却标成「单条记忆钉住的字节数」——那读起来是 B，两者差 26 倍。**
> 代码审查查出此处（建议 3）。A 回答的是「每条引用**摊到**多少」，B 才是
> 「一条记忆**钉住**多少」；因为豁免是会话粒度，**一条记忆确实钉住整个会话**，
> 所以标题问的那个问题，答案是 B。**分母与口径不写明，数字就会被读成另一个数字。**

按「钉住的字节」重新分类：

```
尚有引用者无 excerpt（回退仍可达）            : 1,460,539 = 29.4%
被未完成 extract job 需要                     :         0 =  0.0%
```

即：**70.6% 的字节正在为一条走不到的代码路径付费**。
（无 excerpt 的证据行：**存活记忆 80/80 = 100% 是 `principal-explicit`**，

## 五、体积与增长（分母写明）

按**日历跨度**（首末 L0 日期 2026-08-23…09-01，**10 天**，含零活动日，保守取法）：

```
496,479 字符/天  →  90 天稳态 42.6 MiB  →  1 年 172.8 MiB（且无上界）
```

> **两处单位标注**（代码审查观察 5）：① 42.6 / 172.8 的除数是 1048576，
> 故是 **MiB** 不是 MB（SI 下为 44.7 / 181.2 MB）；② 该速率的被测量是
> `length(text)` 即**字符**，换成 UTF-8 字节还要再乘 **1.32×**。

### ⛔ 更正：本节初稿那个「占平台日志 4.4%」的对照口径是错的

初稿拿 strataloom 的 L0 与 `~/.dsh/sessions` 比，犯了**两处方向相反**的口径错误
（评审查出，主 agent 已独立复算确认）：

| 错误 | 方向 |
|---|---|
| 平台日志是 **zstd 压缩**字节，strataloom 是未压缩 —— 实测压缩比 **2.41×** | 低估平台侧，**不利于**「体积无害」 |
| 分子是**一个项目**，分母却是**全机 13 个项目**的日志 | 高估平台侧，**有利于**「体积无害」 |

**两个错误部分抵消**——这正是 ADR 0009 §七 记过的判例形状：
「两个错误口径产生一个正确答案，最终数验算通过会掩盖中间量不可用」。

### ⛔ 再更正：上面那个 3.45% **仍然是错的**，而且错在它自己刚立的规矩上

代码审查（必修 2）查出：3.45% 的分子分母**同时**犯了范围与单位两个错误——
**就写在「必须同范围同单位」这句话的下一行**。

| | 分子 | 分母 |
|---|---|---|
| 3.45%（错） | **全部 8 个 repo 库**的 L0，且单位是 `length()` 的**字符** | **仅 strataloom 一个项目**的日志，单位是**字节** |

范围错成了初稿的**镜像**：初稿是「分子一项目、分母全机」，这次是
「分子全部库、分母一项目」——**方向反了，仍是同一个错**。
单位错在 `length(text)` 返回**字符**，而中文 L0 实测 UTF-8 膨胀 **1.32×**。

**同范围（都是 strataloom）同单位（都是字节）的正确值**：

```
strataloom 自己的 repo 库（meta.repo_source = remote:github.com/Alan-IFT/strataloom）
  L0 文本  2,995,704 字符 → UTF-8  3,968,270 字节
strataloom 项目的平台日志
  压缩 60,468,302 → zstd -dc 解压 145,632,112 字节

3,968,270 / 145,632,112 = 2.72%        ← 正确的数
```

> **同一个 zstd/口径错误，ADR 0009 §七 一次、本文 §五初稿一次、本文更正稿一次
> ——这是第三次。** 前两次都是「发现并改正」，第三次是**在写下防错清单的同一段
> 里再次踩空**。所以真正的教训不是「要同范围同单位」这句话不够醒目，而是：
> **一条只靠人记得去执行的检查项，就是没有实现的检查项**——与本仓
> 「`ROLLUP_TARGET_CHARS` 只存在于提示词里」「extract 的 no secrets 是请求不是机制」
> 完全同型。写进文档只能提醒，挡不住。

**结论不变且更强**：体积**不构成动机**——**2.72%**，比前两个错数都低，
而平台自身的 session 日志在本机同样无轮转（08-22 至今仍在）。
ADR 0009 §七「零损害实例」在**体积维度**成立，本轮以第三次修正后的口径复核通过。

## 六、任何修法必须尊重的四条约束（已实测，勿凭直觉绕过）

1. **不能「有 excerpt 就删 L0」**。excerpt 背后的 L0 仍是更完整的原文，
   删掉＝**为节省磁盘永久销毁证据**，是 D3 的反转，与 ADR 0012 §六第 4 项
   登记的取舍直接冲突。

   **口径必须写全**（代码审查按不同定义复算得 58/349，一度判本条证伪；
   经三方复算，两个数都对，量的不是同一件事）：

   | 判据 | 数 | 说明 |
   |---|---|---|
   | 长度**恰好 400** | 244 = 69.9% | 旧 join-then-truncate 写者切在 `EXTRACT_EVENT_EXCERPT_CHARS` |
   | 以 `…` **结尾** | 33 = 9.5% | 新写者 `capEventText` 的每事件截断标记 |
   | 两者**并集**（初稿的 79.4%） | **277 = 79.4%** | 二者交集为 **0**，故可直接相加 |
   | 仅按 `…` 判（审查所用） | 58 = 16.6% | **漏掉了「恰好 400」这一类**——旧写者切完**不加**省略号 |

   **「恰好 400」是真截断签名，不是巧合**——长度直方图 395..405 区间：

   ```
   395:0  396:1  397:0  398:2  399:5  400:237  401:0 ... 405:0
   ```

   349 条里 237 条堆在恰好 400、两侧几乎为空，自然文本不可能如此。

   > **两处单位说明**：表中 244 是 JS `.length`（UTF-16 码元），直方图 237 是
   > SQLite `length()`（码点），差的 11 条含代理对。**以 244 为准**，因为
   > `capEventText` 用 `text.slice()` 切的就是码元（`extract.ts:65-68`）——
   > **判据必须与写者用的那把尺子同单位**。
   >
   > **更强、且不依赖任何截断判据的论据**：**349/349 = 100%** 的 excerpt
   > 都短于其所在会话的 L0 全文。所以「L0 是更完整的那一份」无需靠 79.4% 支撑。
2. **`metrics.ts` 与 L0 同表耦合**。`recallMissRate` 用
   `SELECT ... FROM conversations WHERE label='tool:memory_recall'`（`metrics.ts:77-86`），
   **无任何时间窗**；实测 **311/311** 条该类行现由豁免保护。任何收窄豁免的改动
   都会**静默移动 ADR 0005 用来决定是否上向量检索的那个数**。
3. **规范承诺须同步**。`plugin-architecture.md:931` 明写
   「被存活记忆引用的会话**永不删除**」——改行为就必须改规范，否则是代码与
   自己承诺的话不一致（ADR 0011 四条教训里占三条的那个形状）。
4. **现有测试抓不到**。`test/layers.test.mjs:106` 今天绿、改后仍绿——它的
   `orphan` 会话由 **tombstone** 记忆引用，走的是另一条分支。**没有任何测试
   让「被引用会话中未被引用的行」穿过 prune**，所以必须先写会失败的测试。

   **变异实测（2026-09-01，主 agent 亲自跑，基线 219 passed / 0 fail）**：

   | 变异 | 结果 |
   |---|---|
   | 整条删除引用豁免子句（只按年龄删） | **变红**（`layers.test.mjs:106`，`actual: []` vs `expected: ['cited']`） |
   | 把年龄条件改为恒真 `(created_at < ? OR 1=1)`（保留形参、不改 arity） | **219 全绿** |

   即：**豁免子句有覆盖，90 天窗口本身零覆盖**。没有任何测试断言
   「一条**未过期**且未被引用的行应当活下来」，所以时间语义可以被任意改动
   而不被察觉。这与本仓「量到最外面那把尺子」的教训同型。

   > 第一次变异写成 `created_at < 99999999999999`（删掉了占位符）导致
   > `column index out of range`，3 个测试因**形参个数**变化而红——那是
   > 语法错误不是行为差异，**不构成覆盖证据**，故改用保留 arity 的写法重测。

## 七、备选方案与最终裁决

- **(a) 不做**：ADR 0009 §七 曾判「零损害实例，本轮不动」。
  代价：L0 无上界，且规范第 931 行与 `L0_RETENTION_MS` 都在陈述一件不发生的事。
- **(b) 豁免降到 seq 粒度**：只保留 `sourceSeqs` 真正引用的行（＋必要邻域）。
- **(c) 承认 L0 永久、删除 `L0_RETENTION_MS` 与时间子句**。
- **(d) 只修文档 + 补测试**：承认现状、更正三处失真措辞，删除行为不动。

### ✅ 裁决：(d)。三个动机里只有两个成立，且都不指向改删除行为

| 动机 | 是否成立 | 指向 |
|---|---|---|
| 体积无上界 | **被自己的数据撤销**（**2.72%**，见 §五两次更正） | 不做 |
| 代码在陈述一件不发生的事（三处失真） | **成立** | 让**文字**追上事实 |
| 该语义零测试覆盖 | **成立**（变异 `OR 1=1` 全绿） | **补断言**，而非删掉未被断言的分支 |

**行为本身是对的**（不删被引用的对话是 D3 要求），错的只是描述。
所以修法是让文字追上事实，不是让行为追上文字。

### ⛔ (c) 被否决——理由登记以防复议

删掉时间子句**不是把一个空转变成空转**，而是把「什么都不删」换成
「**每个维护轮删除一切尚未产出 evidence 的会话**」。L0 写入与 evidence 写入之间
存在**必然时间窗**：

- `captureTurn` 在回合边界**无条件**写 L0（规范承诺：记录「说过什么」不取决于是否想提炼）；
- evidence 只在 extract 作业完成后才写（`extract.ts:335`）；
- `ENQUEUE_MIN_TURN_TOKENS = 200` 以下的回合**永不入队**，永远没有 evidence；
- `extract.ts:327` 模型判定无可记时 `return`，**一条 evidence 都不写**。

**直接复现（主 agent 实测，`/tmp/ctest`）**——一条 5 秒前捕获、尚未提炼的回合：

```
rows before                : 1
after CURRENT predicate    : 1   ← 存活（时间子句保护了它）
after (c) citation-only    : 0   ← 被删除
```

**这类会话在真实数据里确实存在，不是构造出来的假想**（主 agent 实测，
按 `json_extract(payload,'$.sessionId')` 与 `$.turn` 配对 L0 回合与 extract job）：

```
有 extract job 的回合 : 93
无 extract job 的回合 : 13   ← 已捕获、从未入队，结构上永远拿不到 evidence
  其 L0 行数          : 982 = 全部 L0 的 14.4%
```

即 **(c) 会在下一个维护轮删掉这 982 行**，而它们正是「只剩原始记录、尚未被
提炼」的那一类。

> **口径纠错**：此表初稿用 `payload LIKE '%"turn":'||?||'%'` 配对，因 shell 转义
> 使模式恒不匹配，得出「93 全部无 job」的**荒谬结论**（100% 无 job 却有 93 个
> job 存在）。改用 `json_extract` 后得到上表。**一个比率算出 100% 或 0% 时，
> 先怀疑谓词而不是先相信结论。**

即 (c) 会删掉**正在进行的会话、未达 token 门槛的会话、零候选提炼的会话**
——恰恰是「尚未被提炼、因而只剩原始记录」的对话，也就是 L0 存在的全部理由。

**且落地时不会有任何红灯**：变异实测 `(created_at < ? OR 1=1)` **219 全绿**。
「测试全绿 + 删数据」是本仓明令警惕的组合。

> **防复议**：变异全绿**不是**「这分支没人要、可以删」的证据，而是
> 「删它时没有安全网」的证据。ADR 0009 §七 当年已把措辞精确定为
> **「尚未触发」而非「从未生效」**，并预警「否则会误导出可以 DROP 的结论」。
> **(c) 正是那个被预警过的结论，这是第二次走到它面前。**
>
> 若将来真要做，唯一诚实的形式**不是删时间子句**（那会删数据），而是
> **连同调用点整个删除 `pruneConversations`** 并正式声明 L0 永久保留。
> 技术上自洽，但今天无人被这 4.96 MB 伤害，故无理由做。

### ⛔ (b) 被否决

`sourceSeqs` 上界 `WORST_SOURCE_SEQS = 10`，故其**上界**也只保留
4290/6813 = **63%** 的行，实际远低于此——即 (b) 会删掉 L0 多数，正撞约束 1
（79.4% 的 excerpt 带截断痕迹，且 **100%** 短于其会话 L0 全文，L0 是唯一完整副本）。
